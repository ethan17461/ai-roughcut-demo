# AI 粗剪工作台

出海火车票短视频业务的 AI 粗剪流水线：输入选题 → DeepSeek 写脚本（3 版 + 规则审核）→ MiniMax 英文配音 → 从素材库配画面 → 国家/平台规则检查 → **生成真的剪映草稿** → 草稿检查 → 人工换镜头、在剪映里精修。

在线查看一次真实运行的回放：https://ethan17461.github.io/ai-roughcut-demo/

右侧有两种检查：草稿检查读取实际生成的剪映草稿和引用文件；成片 AI 评测需要先在剪映导出视频，在本地工作台选择导出的文件并点击评测。请选刚导出的这一条，评测会用到这次粗剪的镜头、字幕和脚本数据。

本地成片评测支持 MP4、MOV、M4V，最长 3 分钟、最大 100 MB。程序在本机把配音转成文字，再按每秒 2 帧把画面和转写文字发送给 DeepSeek；原始音频不会发送。实测一条 24 秒的视频约 15 秒出结果，花费约 ¥0.13（合规全检约 ¥0.10，打分约 ¥0.03）。本地语音识别默认使用 faster-whisper 的英语 small.en 模型，首次使用需联网下载约 0.5 GB 的模型文件。

成片使用七个维度共 100 分：开头吸引力 20、内容价值与故事 20、画面与内容匹配 15、剪辑节奏与完整度 15、配音与声音 10、字幕与手机观看体验 10、行动引导与分享意愿 10，共 21 个小项，每一项都自动给分。8 项从粗剪数据直接算（镜头时长、切点、地点、脚本审核、字幕、行动引导），4 项靠测量（响度、语速、背景声、画幅），9 项由 AI 看画面和转写判断。人可以改任何一项，但不是必须填。分数不能预测爆款。

合规（人脸、国旗、品牌标识）按每秒 2 帧全检，模型必须对每一帧都写出看到了什么再下结论。查到的内容列出起止时间，点一下就跳到那一段，由人决定「退回修改」「保留并说明」或判为误报；没查到就算通过。结论只有三种：通过、转人工、不合格。只有这些情况转人工：合规有命中或有画面没查成、有小项算不出分、AI 把握不足的小项超过 2 个、总分低于 70、脚本里有待核对的说法。人工选了「退回修改」才是不合格。

在线展示页是某次运行的静态回放，更新代码后需要重新生成并发布页面才能看到新检查结果；旧展示数据可能没有新格式的检查结果。

本地工作台（能输入选题现场生成）：先安装 `requirements.txt` 中的依赖，在 `.env` 里填 DeepSeek 和 MiniMax 的 key；成片评测需要 `DEEPSEEK_API_KEY`。运行 `.venv/bin/python studio.py`，打开 http://localhost:8770 。如果端口被占用，可运行 `PORT=18770 .venv/bin/python studio.py`，改为打开 http://localhost:18770 。不要把密钥发给他人或提交到仓库。

素材来自 Pexels（免费可商用，共 53 段）；选题池的历史数据为示例数据；剪映草稿由开源库 [pyJianYingDraft](https://github.com/GuanYixuan/pyJianYingDraft) 生成。

## 小组共用 Dify 视频评测

组员直接打开 [小组视频评测](https://udify.app/workflow/JVeJSkbtopElpyFe)，上传视频、选择语音语言后点击“运行”。无需下载项目或填写密钥，也不依赖维护者的电脑开机。首次使用时，脚本和人工核验可以留空。

工作流下载和维护说明见 [Dify 评测说明](dify/README.md)。云端已于 2026-11-09 发布，画面分析、实际音轨转写和证据评分已用真实视频跑通；GitHub 保存代码与工作流，Dify 负责在线运行。原工作台评分视觉保持不变。

Dify 当前只自动初评 5 个小项、最多覆盖 27 分，其他项目须人工核验，不能将 27 分折算为 100 分。最终只显示“评分”“安全、转人工”，有建议才显示“优化建议”；人脸、国旗或竞品 Logo 任一人工确认出现即不合格。

## 在自己电脑上继续改

```bash
git clone https://github.com/ethan17461/ai-roughcut-demo.git
cd ai-roughcut-demo
```

怎么跑、哪些是真的哪些是简化的，都写在 `AGENTS.md`，用 Codex 编辑时它会先读这份说明。要把修改推回这个仓库，需要仓库主人在 Settings → Collaborators 里把你加为协作者。成片评测和 Dify 工作流最早在 `yubb6688-alt/ai-roughcut-demo` 分叉里开发，已合并进本仓库。
